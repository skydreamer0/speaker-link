# Windows device-free preview packaging

This is build tooling for a **local preview assembly**, not an installer, signed release,
hardware validation or approval to distribute binaries. The App remains an explicitly
synthetic, device-free UI. Nothing in this procedure enables discovery or speaker control.

## What this slice provides

`tools/package-windows-portable.py` uses Python 3.10+ standard-library modules only.
It never invokes Cargo, Git, the EXE, a shell, a network service or a device API.
Without `--output`, it only reads the supplied staging directory. With `--output`, it
creates one new ZIP; it never replaces an existing file.

The packager checks x64 PE32+ EXE header sanity, receipt/file checksums, exact declared
dependency-to-notice coverage, safe paths, and an explicit payload allowlist. It rejects
Linux executables renamed `.exe`, other architectures, DLLs, missing notices, symlinks,
unexpected files and changed artifact hashes. PE header sanity is **not** a full loader,
Authenticode, malware, provenance or runtime check. A supplied receipt is an assertion
from the builder, not a trusted attestation generated by this tool.

Two assemblies from identical inputs produce identical ZIP bytes: stored entries,
sorted names, fixed timestamps and permissions. This is reproducible **packaging**;
it does not establish reproducible Rust compilation.

## Prerequisites and hard boundaries

1. Use the reviewed App source commit and its unchanged `Cargo.lock`. Record the exact
   Rust compiler and Windows/MSVC SDK versions separately in the private validation record.
   Do not treat `cargo check --target x86_64-pc-windows-msvc` as an EXE build.
2. A Windows operator with an existing approved toolchain must actually build the EXE:

   ```powershell
   cargo build --locked --release --target x86_64-pc-windows-msvc -p speakerlink-app --features native-ui
   ```

   This document does not start that command, install a toolchain, or authorize access
   to a user's computer. Record the command's exit status. The expected artifact is
   `target/x86_64-pc-windows-msvc/release/speakerlink-app.exe`.
3. Review the exact Windows normal/build dependency graph for that lockfile and feature
   selection, plus the actual linked compiler/runtime and bundled font assets. The
   source review in [APP_DEPENDENCIES](APP_DEPENDENCIES.md) is a starting point, not a
   complete binary-notice package. Include Rust standard-library obligations even
   though Cargo.lock does not list them. Preserve Hack/Bitstream, Ubuntu, icon-font
   and other actual notices, not only crate SPDX labels. No notice text is invented here.
4. The current App slice has only cross-target compile evidence, not Windows execution
   evidence or a Windows EXE delivered by this packaging change. Missing EXE or notices
   blocks assembly. Do not replace missing production artifacts with test fixtures.

## Dedicated staging directory

Only these files are accepted. Extra logs, PDBs, raw traces and private machine paths
must not be placed here; the tool rejects unlisted files rather than copying a whole folder.

```text
preview-staging/
  speakerlink-app.exe
  LICENSE
  THIRD_PARTY_NOTICES.md
  build-receipt.json
  dependency-graph.json
  notice-inventory.json
  notices/
    ...actual reviewed UTF-8 copyright/license texts...
```

Create the three JSON files from actual build/review evidence. The following field
shapes are examples, **not completed receipts**; replace every placeholder. The parser
rejects unknown or duplicate JSON fields. Keep local absolute paths and device data out.

`build-receipt.json`:

```json
{
  "schema": 1,
  "mode": "device-free-preview",
  "source_commit": "<40 lowercase hexadecimal characters>",
  "version": "0.0.0-dev",
  "target": "x86_64-pc-windows-msvc",
  "rustc": "rustc <actual version and commit>",
  "cargo_lock_sha256": "<actual Cargo.lock SHA-256>",
  "artifact_sha256": "<actual EXE SHA-256>",
  "dependency_graph_sha256": "<exact dependency-graph.json bytes SHA-256>"
}
```

`dependency-graph.json` contains `schema: 1`, `target`, `cargo_lock_sha256`, and
`components`, an array of `{"name": "...", "version": "..."}`. Record each exact
selected third-party package, the project as `speaker-link`, compiler runtime as
`rust-std`, and embedded font assets as `Hack-font`, `Ubuntu-font`, `egui-icons-font`.
Use the actual upstream version/revision token for each. The mandatory GUI/font
categories reflect this App slice, not a universal license-completeness algorithm.
Re-review this contract if the bundled fonts or renderer change.

`notice-inventory.json` contains `schema: 1`, `artifact_sha256`, and `components`.
Every graph component must have exactly one corresponding entry:

```json
{
  "name": "<component name>",
  "version": "<exact graph version>",
  "license": "<reviewed expression / selected license path>",
  "source": "https://<public exact-version source>",
  "notices": [
    {"path": "notices/<actual-file>.txt", "sha256": "<exact file SHA-256>"}
  ]
}
```

A component can reference several notice files; shared files may be referenced by
multiple components. Paths must stay under `notices/`, use ASCII letters/digits and
`._/-`, and have no traversal, Windows reserved names or case-colliding filenames.
Verify license-text completeness and copyright retention manually. Graph coverage
alone cannot detect a component omitted by the person preparing both input files.

## Check and assemble

Run from the repository with an existing Python installation:

```powershell
python tools/package-windows-portable.py preview-staging
python tools/package-windows-portable.py preview-staging --output artifacts/speaker-link-preview.zip
```

Create `artifacts/` first. The output must be outside staging and must not already exist.
On a validation error the command exits 2 and creates no archive. An I/O failure after
creation can leave a partial ZIP; do not use it without a success result and matching
reported checksum. Use a new filename for a later attempt, never silently overwrite.
Success reports the ZIP hash and explicitly says `release_approval: false` and
`native_window_validation: NOT_RUN_BY_PACKAGER`.

The archive contains one versioned directory, a preview warning, all allowed inputs,
and `SHA256SUMS.txt` covering every other archived file. The packager does not launch
the application and adds no auto-start script or installation action.

## Windows no-device acceptance, still separate

After checking the artifact's trusted source, checksum and notices, a Windows operator
can perform this manual checklist without pairing or connecting any speaker:

- Extract into a new ordinary directory with spaces in its path. Do not run as admin.
  Record Windows build and whether graphics/runtime dependencies are available.
- Launch the reviewed EXE. Confirm “Device-free UI preview” and “SYNTHETIC DATA ONLY”
  remain visible, with an empty initial state and all real device controls disabled.
- Exercise all five synthetic states. Confirm unknown values are not zero, stale
  values are labeled, and Clear resets the display after repeated state changes.
- Resize at 100%, 150% and 200% Windows display scaling; inspect text, focus, keyboard
  navigation, close/reopen and unavailable graphics/runtime errors. Missing accessibility
  or CJK support remains a limitation, not a passing result.
- Confirm closing ends the App process and no worker persists. Do not probe Bluetooth
  to test this package. Hardware/driver/F1–F4 validation is out of scope.
- Do not bypass SmartScreen, signature, antivirus or other security warnings. Record
  the blocker and stop; this source package does not sign artifacts or alter policies.

Record exact commit/EXE/ZIP hashes and PASS, FAIL, NOT_RUN or BLOCKED for each item.
No step here establishes the binary is self-contained on every Windows installation,
or that real speaker functionality is ready. A release still needs the original gates.

## WGPU source-bound preflight (2026-10-25 candidate)

The legacy mode remains readable for historical fixtures. Its result now explicitly says
`source_contract_validation=NOT_RUN_LEGACY_INPUTS`; **it is not current WGPU acceptance**.
For WGPU, use the independently reviewed `wgpu-source-contract.json` supplied alongside
this source-only candidate, pinned to PR #12 commit
`bf85b63a65f0f46b0816304b903c023422cc5e40`, not mutable `main` or an earlier Glow graph.

```text
python tools/package-windows-portable.py preview-staging --source-contract wgpu-source-contract.json
```

Do not supply `--output` until the actual release artifact and its notice review exist.
The strict mode extends the existing validator, with no Cargo, network, device or EXE
execution. In addition to the legacy payload, staging requires:

- `Cargo.lock`: exact source bytes; SHA256
  `1b612db350be1fe9828b4066b46ab917e032e581d72dfed58f57fc0fda1b8210`.
- `app-Cargo.toml`: exact `crates/speakerlink-app/Cargo.toml` source bytes; SHA256
  `442aaeed0420693867f56328dcc898978439a94ec89126f60af030f26a763e1f`.
- `artifact-provenance.json`: builder evidence using **only** these fields:
  `schema` (1), `source_commit`, `target`, `profile` (`release`), `features`
  (`["native-ui"]`), `artifact_path`, `artifact_sha256`, `source_url`,
  `build_evidence_url`, and `build_command`.

`artifact_path` must be `target/x86_64-pc-windows-msvc/release/speakerlink-app.exe`.
`build_command` must be the locked release command in prerequisites above.
`source_url` must be the exact GitHub tree URL ending in the 40-character source SHA.
`build_evidence_url` must identify a run (optionally attempt and job) under
`https://github.com/skydreamer0/speaker-link/actions/runs/`.
Record the actual EXE's SHA256, not the source ZIP hash, Git SHA, or synthetic fixture hash.
A hosted debug smoke is **not** evidence of this release build. The existing successful
run 40208658495 has no release artifact demonstrated by this package preparation.

Strict preflight requires exact dependency identity equality with the reviewed Windows
normal/build source graph, not only the 21 newly added lock packages. This candidate has
142 Cargo components (140 registry archives with verified Cargo.lock SHA256 and 2 local
workspace components). Supplemental records cover the project and bundled Hack, Ubuntu,
and egui-icons fonts; `bundled-epaint-0.37.0` means the font's supplying crate revision,
not an invented upstream font version. `rust-std` must match the actual `rustc` version.
Every component still requires exact notice coverage and real hashed UTF-8 notice files.
WGPU family omissions, wrong versions, a stale source/lock, debug artifact paths,
missing build evidence, and mismatched EXE hashes are rejected.

A supplied URL is checked for consistency/shape **not remotely attested**. A successful
result proves only input consistency; a builder could still supply false assertions.
Independent review must verify the exact workflow job, command, source, feature flags,
compiler/SDK, downloaded artifact bytes and link/runtime inventory. This candidate's
source graph conservatively includes build dependencies; it is not a reconstructed
binary-linkage graph. If the actual artifact contains additional redistributable runtime
components, update/review the source contract and actual notice inventory before assembly;
do not remove runtime components merely to make equality pass. System runtime/SDK and
compiler notices remain an explicit builder/reviewer gate.

The packaging result includes the source-contract SHA256. Assembled ZIPs include the
contract and its checksum in SHA256SUMS. This is not a trust signature. An absent
contract never silently claims source validation; `NOT_RUN_LEGACY_INPUTS` is distinct
from strict `PASS`. Neither output grants release approval or marks local GPU tests done.
