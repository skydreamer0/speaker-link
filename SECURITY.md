# Security and sensitive information

There are no released versions to support yet. Do not attach raw Bluetooth captures, MACs, serials, private device names or full local logs to public issues.

If GitHub shows a "Report a vulnerability" action under this repository's Security tab, use it for private reports. Private vulnerability reporting is not yet confirmed enabled. If that action is absent, open a public issue containing only a request for a private reporting channel; do not include vulnerability details or identifiers. A maintainer must establish a private channel before collecting those details.

A report should include the affected commit/version, impact and a minimal sanitized reproduction. Avoid testing on other people's devices. Device writes must stay within the tested capability policy. No automatic uploads, network control server or arbitrary Bluetooth command interface is planned for the first release.

Maintainers must enable and verify a private reporting channel before publishing runnable binaries. Do not promise response deadlines until maintainers can meet them.
