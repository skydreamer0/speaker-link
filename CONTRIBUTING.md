# Contributing

Start with [SPEC](docs/SPEC.md) and the relevant tracking issue. The project is currently documenting and validating its first hardware target. Please do not claim working support without a reproducible hardware report.

Open an issue before changing protocol behavior, public APIs, dependencies or scope. A small documentation correction can go directly to a PR. Each PR should explain the user-visible result, acceptance condition, tests actually run and hardware limitations.

Contribute work you have the right to license under MIT. Contributions to this repository are offered under its MIT license. Preserve third-party notices and identify copied or adapted material, its original URL, version and license. Do not submit leaked firmware, proprietary app code, credentials, copied branding or unreviewed packet captures. Translating GPL code into Rust does not make it MIT.

No CLA or automated release process is currently configured. Code CI and release procedures will be added with implementation. Do not add a passing badge until a real workflow exists and passes.

Treat other contributors respectfully. Harassment and disclosure of private data are unacceptable. Maintainers can remove harmful content and limit participation. Use public issues for product discussions; use the private reporting guidance in SECURITY.md for vulnerabilities.
